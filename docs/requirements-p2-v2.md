# lisa P2：每天一页（需求 v2）

> 状态：需求（做什么、为什么）。设计以 design.md 为准，本文经评审后合入 design 和 contract，编码不直接依据本文。
> 权威顺序：requirements.md → 本文 → design.md → contract.md。
> 取代：`requirements-p2-interaction.md`（Hermes 版，已归档至 docs/archive/）。它的 A、B、C 三项需求保留，重新组织在本文的总纲之下。

## 0. 总纲

**每天都是今天，每天都是生活的一页。昨天是今天的回忆，明天是今天的预告。**

lisa 的基本单位是"天"。每一页会经历三种状态：

| 时刻 | 这一页是 | 由谁写 |
|---|---|---|
| 前一晚 | 预告：明天要发生什么、要准备什么 | 夜间任务（27B） |
| 当天 | 今天：正在发生的事、要你动手的事 | 采集实时写入，小模型做摘要 |
| 之后 | 回忆：发生了什么、决定了什么、答应了什么 | 夜间合页（27B），之后只追加补记 |

lisa 每晚合上一页，同时写好下一页的开头。卡片菜单、审批、记忆页、聊天都是这一页的组成部分，或者是查阅这本书的方式。

这本书从上线那天开始写，之前是空白。不做回填，这不是缺陷。

## 1. 时间原则

- **T1　以此刻为准计算。** 任何时候打开 lisa，页面都按打开那一刻的时间计算和渲染：哪些日程已过、离截止还剩几天、卡片是否过期、"明天"具体是哪天。
- **T2　模型不写相对时间。** 模型的输出只能写绝对时间（日期、时刻）和结构化字段（`due_at`、`starts_at`、状态）。"今天""明天""还剩 3 天"这类文字由渲染层计算生成。校验器检查模型文本，发现相对时间词就拒绝并修复一次，仍不通过就丢弃这条。
- **T3　内容注明截至何时。** 每一段都显示它的时间点，例如"采集截至 14:32""判断截至今晨 04:40"。数据源缺失时直接写出来，例如"iMessage 已 3 小时未更新"。页面呈现的是 lisa 此刻所知的情况，不能等同于此刻的全部事实。
- **T4　每条事实有两个时间。** `occurred_at` 是发生时间，`ingested_at` 是 lisa 得知的时间，两者都是一等字段，参与查询。晚到的数据按发生时间归入对应的页，按得知时间标为补记。
- **T5　合上的页不改写，只追加。** 页合上之后，晚到的数据和修正都以补记形式追加在那一页，注明"补记于 X"。每一页都保留当时 lisa 知道什么。

## 2. 一天的边界

- **D1　一天从当地时间 04:00 开始**（可配置，`day.boundary_local: "04:00"`）。凌晨 00:00–03:59 的活动归入前一天那一页。
- **D2　时区按你当时所在地判定。** 以主设备（手机或当日有活动的 node）报告的时区为准，出差当天那一页可能长于或短于 24 小时。
- **D3　合页时间。** 第 D 天在 D+1 的 04:00 截止，之后才能合页。夜间窗口相应调整见 §4。

## 3. 一页的结构

一张 `/today` 或 `/day/YYYY-MM-DD` 页面分为四部分。

| 部分 | 内容 | 早上侧重 | 晚上侧重 |
|---|---|---|---|
| 昨天回顾 | 两三句话，只写和今天有关的延续：昨天答应的事、没回的消息 | ✔ | |
| 今天：卡片 | 3–5 张需要你动手的卡片，每张附带已准备好的下一步 | ✔ | ✔ |
| 今天：记录 | 今天发生了什么：简短叙述、照片描述、见过的人、读过的东西，不需要处理 | | ✔ |
| 明天预告 | 明天的日程和需要提前准备的事 | | ✔ |
| 页脚 | 各数据源状态和截至时间（T3） | ✔ | ✔ |

- 页面按打开时刻调整各部分的展开顺序，早上先显示回顾和卡片，晚上先显示记录和预告。内容不变，只是顺序变化。
- **性能指标：早上在手机上 30 秒内看完回顾和卡片。**
- 过去的页可以前后翻页（`/day/…`）。每周日晚上额外生成一张周页（`/week/YYYY-Www`），回顾这 7 天。
- 页面里的人物、项目链接到 brain 条目；brain 条目反向列出提到它的每一页。

## 4. 夜间任务：合页与写预告

**输入**（不把前几天的 digest 全部塞进去）：
- 当天的全部事件（已完成 map 的部分直接复用）；
- 所有未结清的承诺（§5）；
- 未来 7 天的日历、提醒和截止日期；
- 当天涉及的人物、项目的 brain 页面；
- 关注清单（§7）。

**输出**：
1. 当天的回忆定稿，即 digest，包括发生了什么、决定了什么、答应了什么，以及提取出的事实和承诺；
2. 下一页的预告和卡片，卡片附带预先生成好的动作提案（§6）；
3. 对前一晚预告的核对：预告里说要发生的事，实际发生了吗？有没有漏掉的？（§8）
4. 当天页面的 markdown 归档（§11）。

**时间安排**（需要在 M2 加 the GPU host 上实测后确认）：
- 02:00–04:00：对当天已到的事件先做 map；
- 04:00 截止之后：补上 02:00–04:00 到达的事件，再做 reduce、写预告；
- 目标是 07:00 前完成。

如果实测装不下，优先保证卡片和预告，回忆定稿可以延后到白天空闲时补完，页面按 T3 标明"回忆整理中"。

## 5. 承诺链：不漏事

- **C1**　夜间合页时提取承诺，包括你答应别人的、别人要求你的、有截止期的。每条承诺有 `due_at`（可为空）、来源事件和状态。
- **C2**　未结清的承诺自动进入之后每一页，不受"往回看 1 天"的限制，直到你标记为已完成、放下或改期。
- **C3**　一件事挂了 7 天没有任何动静，就在页面上问你一次：继续、放下，还是改期到某天？问过之后不再重复问，直到改期的日子到了。
- **C4**　卡片数量有上限（3–5 张）。超出上限的承诺折叠成"另有 N 项"，展开可见，不会消失。

## 6. 卡片与动作（审批台）

每张卡片包括：一句话、截止信息（按 T2 渲染）、溯源链接、预先准备好的下一步。

**标记选项**：已处理 / 忽略 / 放下 / 执行准备好的动作。每一次标记都记录下来，作为排序的反馈（§8）。

**动作层**（沿用 openmuse 模式）：
- **A1　内容哈希绑定。** 哈希覆盖规范化后的完整载荷，包括目标提醒列表或日历、标题、时间、备注。内容一变，旧的批准作废。
- **A2　两个计时器，含义不同：**
  - 提案有效期：到对应截止时刻，或到这一页结束（次日 04:00），取较早者。夜间生成的提案早上仍然有效。
  - 执行窗口：批准后 30 分钟内必须开始执行。超时回到"待批准"，一键就能重新批准。
- **A3　状态机：**
  ```
  drafted → waiting_approval → approved → executing → done
                 │                │           ├→ failed
                 ├→ rejected      │           └→ outcome_unknown（等你确认，不自动重试）
                 ├→ expired       └→ （执行窗口超时）→ waiting_approval
                 └→ superseded（内容哈希变化）
  ```
- **A4**　执行机离线时，显示"等待执行机"，不静默失败。
- **A5**　每个动作留回执：做了什么、结果如何、由哪条事件触发、谁在何时批准的。
- **A6　v1 的动作范围只有新建 Apple 提醒和日历事件。** 不代你发消息或邮件（与 requirements 的范围外约定一致）。
- **A7**　建议用商量的口气写**（"要不要把 X 挪到 Y？"），执行需要你批准。

## 7. 关注清单

- 由你手工维护，比如：女儿学校、体检、某个项目。每项可以附带关键词、关联的人物或实体。
- 用于卡片排序加权和预告筛选。冷启动时数据少，主要靠它来排序。
- 在 `/memory` 里编辑，也可以直接在 `/ask` 里说"以后帮我关注 X"，由 lisa 生成一个待你确认的修改。

## 8. 反馈与自我核对

- **F1**　卡片标记（§6）写入反馈表，用来调整排序和提前量（§9）。
- **F2**　每晚把前一晚的预告和实际发生的事逐条对照，记录命中、落空、遗漏，形成预告准确度指标，显示在健康页上。
- **F3**　评测集：挑 10 个真实的日子和 10 个你关心的问题，记下标准答案。换模型、改提示词或切换推理来源之前，必须先跑评测集并对比结果。

## 9. 预告的提前量

未来 7 天会整体扫描，但一件事只在"今天该开始准备"时才上页面。

| 类型 | 默认提前量 |
|---|---|
| 普通日程 | 1 天 |
| 需要回复或预约的事 | 3 天 |
| 需要准备东西的事（表格、礼物、出行） | 7 天 |

以上是可配置的起点，之后根据 F1 的忽略率调整。关注清单里的事项可以单独设置提前量。

## 10. 白天：增量更新

- 今天这一页的"记录"部分直接展示当天已采集的事件。用 M2 上的 2B 小模型写一句话摘要，不用等到夜里。
- 小模型对新事件做分拣：只有与已有卡片或承诺相关、或者带明确截止期，才处理。
  - 与已有卡片相关的，给卡片标"有更新"，必要时触发一次白天的增量重算，排在夜间处理之后、让位给交互请求；
  - 新出现、带截止期的，生成一张新卡片的草稿。
- 即时推送（Web Push，只推标题）每天最多 3 条，早上的"今天 N 件事"算作其中一条。

## 11. 归档：这本书要比 lisa 活得久

- 每页合上时，导出一份纯 markdown：`archive/YYYY/MM/DD.md`，内容包括回忆、记录、照片描述、当天的承诺和动作回执。补记也追加到同一个文件。
- 周页导出为 `archive/YYYY/Www.md`。
- 归档目录纳入 restic 备份。库仍然是正本，归档是为了不依赖 lisa 的代码也能读。

## 12. 记忆页（/memory）

- 查看 brain 的人物、项目、地点条目：汇总后的事实、时间线，以及提到它的每一页。
- 可以修正和删除：修正作为你做出的更正事实写入，优先级高于模型提取的事实；删除走现有的 forget 流程（tombstone）。
- 关注清单在这里维护。

## 13. 聊天（/ask）

- 以消息流的形式呈现，历史可以回滚。
- 检索范围包括 digest、brain、承诺，以及**当天的原始事件**。不能因为今天还没合页，就答"记忆里没有"。
- **用代码校验引用。** 回答里的每一处引用必须对应库里真实存在的事件、digest 或事实，校验不通过的句子删除。一处有效引用都没有时，回答"记忆里没有"，不编造，也不只是标注"推测"就输出。
- 你提的问题作为生活事件入库；lisa 的回答标记为 `source=lisa`，**不参与事实提取**，防止自己的输出被当作记忆引用。
- 推理走你的网关。以后如果改用云端模型，按 §16 的第 4 项记录决定。

## 14. 不做什么

- 不做原生 App：手机用 Safari 加 PWA，通过 tailnet 访问。
- 不做浏览器 agent、云端电脑，不做支付、购物，不做代发消息或邮件。
- 不做多用户，不做社区技能市场，也不做让你自己配置的定时任务系统。
- 健康数据（睡眠、HRV、步数，通过 iPhone 快捷指令推送）列为 **P3 候选**，不进 P2。

## 17. 验收案例

1. **医生邮件。** 邮件到达后，当晚或白天增量生成一张卡片："体检预约 9/30 截止"，下方附带准备好的"建提醒"提案。第二天早上一键批准，Apple 提醒建好，回执可以追溯到那封邮件。
2. **女儿学校。** 问"我女儿学校最近有什么事？"，回答引用邮件、日历、提醒，每条都能点开溯源；没有相关数据时回答"记忆里没有"。
3. **承诺不漏。** 周一答应"周三前回复 X"。周二、周三的页面都出现这件事，直到你标记完成。挂满 7 天未处理的事，页面会问你一次。
4. **晚到的数据。** 笔记本合盖一晚，第二天上午才上报的数据，归入前一天那一页的补记，前一天的原文不变，页脚显示当时这台机器缺席。
5. **此刻为准。** 下午 14:00 打开页面，09:00 的会议显示为已过；距离截止显示"还剩 2 天"，而不是模型昨晚写下的"还剩 3 天"。

  closed_at     timestamptz
);

-- X8 卡片与反馈
CREATE TABLE memory.cards (
  id          bigserial PRIMARY KEY,
  day         date NOT NULL,             -- 属于哪一页
  kind        text NOT NULL,             -- commitment/health/change/prep
  title       text NOT NULL,
  due_at      timestamptz,
  rank        real NOT NULL,
  proposal_id bigint,                    -- 预先准备的动作，可空
  sources     bigint[] NOT NULL,
  as_of       timestamptz NOT NULL,
  stale       boolean NOT NULL DEFAULT false   -- 白天"有更新"
);
CREATE TABLE memory.card_feedback (
  card_id bigint NOT NULL,
  action  text NOT NULL,                 -- done/ignore/drop/execute
  at      timestamptz NOT NULL DEFAULT now()
);

-- X10 关注清单
CREATE TABLE memory.focus (
  id        bigserial PRIMARY KEY,
  label     text NOT NULL,
  keywords  text[],
  entities  bigint[],
  lead_days int,                         -- 可覆盖默认提前量
  active    boolean NOT NULL DEFAULT true
);
