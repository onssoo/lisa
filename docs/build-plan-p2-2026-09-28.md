## 1. 阶段与验收

### P2.0 地基

**内容**：开工门槛核对（上表）；时间原则 T1–T5（contract §10.1b）；04:00 分界
（`day.boundary_local`，§10.1）；markdown 归档 `archive/YYYY/MM/DD.md`（§12.7）；
按角色配置模型 `inference.roles.{main,small,embed,rerank}`（§2，X14，含
`embed_model_id`/维度不一致拒写）；迁移 `0003_p2_pages.sql`（P2 表 + `ingested_at` 索引）。

**验收**：
- [ ] 一页合上后生成 `archive/YYYY/MM/DD.md`，内容可读（无 lisa 代码也能读）；
- [ ] 下午打开页面，上午的日程显示为已过（T1 以打开时刻计算）；
- [ ] 模型输出含相对时间词时，校验器拒绝并修复一次，仍不通过则丢弃（V10）；
- [ ] 换 embed 模型/维度后写入被拒（`EMBED_MODEL_MISMATCH`），旧行由白天 lane 重嵌；
- [ ] 02:00–07:00 夜间窗口在 M2+the GPU host 联跑下实测可行（§4 时间安排的实测确认）。

### P2.1 今天这一页

**内容**：`/today` 四个部分（§12.6）；卡片附带预先生成的提案（X8）；审批台（§6，X9 双计时器）；
承诺链（§5，X7，C1–C4）；关注清单（§7，X10）。

**验收**（requirements §17 案例 1、3）：
- [ ] **案例 1（医生邮件）**：邮件到达后，当晚或白天增量生成卡片「体检预约 9/30 截止」，
      下方附「建提醒」提案；次日早上一键批准，Apple 提醒建好，回执可追溯到那封邮件；
- [ ] **案例 3（承诺不漏）**：周一答应「周三前回复 X」，周二、周三页面都出现，直到标记完成；
      挂满 7 天未处理的事，页面问一次，问过后不重复问（C3）；
- [ ] 卡片 ≤ 5 张，超出折叠「另有 N 项」（C4）；
- [ ] 提案有效期到次日 04:00 为止（夜间生成的提案早上仍有效）；批准后 30 分钟未执行回到
      待批准，一键重批（A2）。

### P2.2 昨天与明天

**内容**：预告和提前量（§9，默认 1/3/7 天，可配置）；前后翻页 `/day/YYYY-MM-DD`；周页
`/week/YYYY-Www`（周日晚）；预告核对 F2（命中/落空/遗漏 → 健康页）；白天增量（§10：
2B 一句话摘要、卡片「有更新」、Web Push 每日 ≤ 3 条只推标题）。

**验收**（requirements §17 案例 4、5）：
- [ ] **案例 4（晚到数据）**：合盖一晚，次日才上报的数据归入前一天补记，前一天原文不变，
      页脚显示当时该机器缺席（T4/T5）；
- [ ] **案例 5（此刻为准）**：14:00 打开，09:00 会议显示已过；「还剩 2 天」由渲染层按
      打开时刻计算，而不是模型昨晚写的「还剩 3 天」（T1/T2）；
- [ ] 周页在周日晚生成，回顾 7 天；
- [ ] 预告核对块出现在前一天页面，健康页显示预告准确度指标。

### P2.3 记忆页

**内容**：`/memory` 查看 brain 条目（汇总事实、时间线、提到它的每一页）；修正（作为 owner
更正事实写入，优先级高于模型提取）；删除（现有 forget 流程，tombstone）；关注清单在此维护。

**验收**：
- [ ] 修正后的事实在下一页被使用（owner 更正优先）；
- [ ] 删除走 forget 流程，tombstone 生效，重新采集被阻止。

### P2.4 聊天

**内容**：`/ask`（§13/§15.2：消息流、历史回滚、检索含 digest/brain/承诺/当天原始事件、
X12 引用校验、X11 自写隔离）；评测集 F3（10 个真实日子 + 10 个关心的问题，标准答案，
换模型/改提示词/换推理来源前必须先跑）。

**验收**（requirements §17 案例 2）：
- [ ] **案例 2（女儿学校）**：问「我女儿学校最近有什么事？」，回答引用邮件、日历、提醒，
      每条可点开溯源；没有相关数据时回答「记忆里没有」，不编造、不只标「推测」；
- [ ] lisa 的回答（`source=lisa`）不出现在后续回答的引用中（X11）；
- [ ] 评测集首次跑通，基线结果记录在案。

## 2. X18 验收证据要求（每个阶段都适用）

每阶段验收必须附：

1. **真实数据**：验收案例用生产库的真实事件（或 owner 提供的真实样本），不用合成数据；
2. **真实登录状态下的页面证据**：浏览器截图或页面 HTML 快照，登录态（session cookie）下
   打开对应页面，标注打开时刻；
3. **路由冒烟测试**：遍历全部路由（`/`、`/today`、`/day/…`、`/week/…`、`/pending`、`/ask`、
   `/memory`、`/pair`、`/health`、`/v1/*` 关键端点），匿名和登录各跑一次，**不能出现 500**；
   匿名预期 303→`/pair`（页面路由）或 401（API），登录预期 200。该测试进
   `tests/integration/test_web.py`，每阶段合并前跑。

## 3. 明确不做（requirements §14）

- 不做原生 App（Safari + PWA，tailnet）；不做浏览器 agent、云端电脑；
- 不做支付、购物、代发消息或邮件；v1 动作只有新建 Apple 提醒和日历事件（A6）；
- 不做多用户、社区技能市场、用户自定义定时任务；
- 健康数据（睡眠/HRV/步数）是 P3 候选，不进 P2。
