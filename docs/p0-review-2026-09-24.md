## B. Defects (block acceptance)

### B1. `pair` crashes — `NameError: token_sha2` (pair.py:60)

Reproduced live:

```
$ python -m lisa_core pair --node review-check --role client
  File ".../api/pair.py", line 60, in create_pair_code
  (token_id, node_id, role, token_sha2),
NameError: name 'token_sha2' is not defined. Did you mean: 'token_sha'?
```

The variable is `token_sha` (line 46); the reference at line 60 says `token_sha2`. **One-token fix.**
Why the tests did not catch it: `grep -rn pair core/tests/` → zero tests touch `create_pair_code`.
Pairing is the only way any browser or node gets a token, so P0's "health page reachable after
pairing" is impossible until this is fixed. **Add a unit test for pair (create → redeem → auth works).**

### B2. worker writes zero output — no logging is configured anywhere

worker.log and worker.err.log are **0 bytes after 5.5 hours** (plist redirects are correct). Root
cause, verified: `grep -rn basicConfig app/` → nothing. The whole codebase never configures the
`logging` root; `serve` only looks alive because uvicorn configures its own loggers. The worker's
`log.info(...)` calls hit a root logger at WARNING with no handler → dropped.

Fix: `logging.basicConfig(level=INFO, format=…)` in `__main__` (both commands), or a `setup_logging()`
helper in `__main__`/`app.py`. Then the scheduler's 5-min tick lines become visible, which is what the
contract's "jobs recorded / failures on the health page" story depends on. Also have `make test` or a
tiny test assert the worker logs at least one line (this is exactly the class of silent failure the
canary work is meant to catch).

### B3. The Swift node does not compile

The commit presents 24 Swift sources as the P0 node skeleton, but:

```
swiftc -parse     Sources/LisaNode/*.swift          → LisaNodeMain.swift:77 error: expected '}'
                                                  (brace opened at line 43, runDaemon)
swiftc -typecheck Sources/LisaNode/*.swift          → 20 errors (Filters.swift AnyCodable misuse, …)
```

This was never built. Note the plan's own prerequisite was also skipped: CLT is still 5.8.1/SDK 13.3
(`swiftc --version` measured on the machine), so even after the syntax fix the macOS-14 branch story
(F3 route) is unaddressed. Minimum to call P0 done: `swiftc -typecheck` clean on all of
`Sources/LisaNode/**/*.swift`, plus a `make node` that produces the universal binary. Contract §24-3
(rebuild+resign keeps grants) cannot run until a binary exists at all.
