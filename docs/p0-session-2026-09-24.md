## 1. tailscale serve — done, after defeating a real upstream bug

- `tailscale serve --bg http://127.0.0.1:8443` is up and **persisted** (`serve status` shows the
  config; reboot-safe).
- The reason it silently failed for an hour of debugging: **tailscale/tailscale issue #19933** —
  the macOS Standalone variant fails to persist Serve config into the Keychain when encrypted node
  state is enabled, and reports "Serve started" anyway. Exact match to our symptoms (v1.98.8,
  Standalone + network extension, `--bg` prints success, `status` says "No serve config", 443
  refused).
- Fix applied (the issue's workaround, with the owner's approval): `EncryptState=false` + Tailscale
  restart. **Trade-off, on the record:** node state is no longer encrypted at rest on stage1-host;
  acceptable for a home tailnet, revisit if tailscale ships a fix. After that, serve persisted
  immediately.
- HTTPS cert issued fine (`tailscale cert` → `~/lisa-core/certs/`, 0600).
